# 実験履歴: 旋回時過渡誤差の原因整理(2026-07-30時点)

15〜18番の結果を1枚に整理する。個々の実験詳細は各番号を参照。

## 確定した原因(証拠あり)

### A. 3つのバグ(修正済み、16番)

実旋回を初めて有効化した際の壊滅的破綻(最大159m、ヨー誤差180°)の原因。
いずれも「yaw=0では無症状」なため、この検証まで一度も発現していなかった。

1. `/odom_fast`のtwistがワールド座標系のまま配信(ボディ座標系であるべき)
2. `body.MoveRotation()`が非kinematic Rigidbodyの`angularVelocity`を更新しない
3. **(真因)** ジャイロが擬ベクトルとして正しく変換されていない
   (`UnityVectorToRos`の鏡映変換に符号反転が抜けていた)

3つとも修正済み。修正後、壊滅的破綻(541/541点非対応等)は再現しなくなった。

### B. 残る過渡誤差は②ではなく③で生まれる(17番)

3段分解(②wall / ③state_estimate / ①odom_fast、真値との突き合わせ)の結果:

- ②(壁マッチング測定)は旋回中も含め**最大2.8mm/0.25°**とほぼ真値
- ③(因子グラフ融合)で最大24.9mm、①はその上に外挿誤差を足して最大28.2mm
- この間、DCSダウンウェイト0件・壁補正拒否0件・unavailable 0件
  (壁補正は**毎回フル重みで受理**されている)

→ 誤差は測定(②)の質ではなく、③の融合の仕方で生まれている。

### C. 融合側の機序: IMU拘束が壁の絶対拘束より硬すぎる(17・18番)

18番のσスイープで機序を実証した。

| 操作 | t=15旋回窓 max[mm] | 判定 |
|---|---:|---|
| baseline | 27.7〜28.2 | — |
| 壁yaw事前分布を締める(0.30→0.05) | 30.5〜30.6 | **悪化**(効果なし) |
| IMUノイズ×10 | 18.3 | 改善 |
| IMUノイズ×30 | **12.1** | 改善(最良) |
| IMUノイズ×50 | 12.0 | 頭打ち(30xと同値) |

「壁を締めても悪化し、IMUを緩めると改善する」という非対称な結果は、
**問題が"壁を信じていないこと"ではなく"IMU(CombinedImuFactor)の相対拘束が
硬すぎて、旋回中の予測を過信すること"**であることを直接裏付ける。データ
シート値のIMUノイズは無回転時は問題にならないが、旋回中の未モデル化誤差
(有限差分加速度・タイミングジッタ等)を吸収する余地が無い。

## まだ特定できていない点

**IMUノイズをいくら緩めても12mm前後で頭打ちになり、5mm目標に届かない。**
つまりIMU拘束の硬さは主要因の一つだが、それだけでは説明しきれない
「もう1つの下限要因」が別に存在する。候補(いずれも未検証):

1. **バイアスのランダムウォークσ**(`bias_acc_random_walk_sigma`/
   `bias_gyro_random_walk_sigma`)は今回のスイープで触っていない。旋回中に
   一時的に誤差を吸収したバイアスが、真値へ戻るのに数秒かかっている
   (=バイアス自身の遅い時定数)可能性がある。18番でスイープしたのは
   加速度計・ジャイロ・積分の「測定」σのみ。
2. **②の共分散が固定値・ヒューリスティックであること**(アーキテクチャ文書
   で以前から指摘済み、17番の対策2)。壁位置の残差は小さくても、旋回中は
   見える壁面の法線方向の分布が変わり、**ヨー方向の真の情報量(観測可能性)
   だけが一時的に落ちている**可能性がある。現状の共分散は対応点数のみに
   基づく(固定1e-5、軸別は機械的折半)ため、この種の幾何学的な劣化を
   反映できない。実際のGauss-Newton Hessianから共分散を出せば、旋回中に
   σが自動的に(必要な分だけ)緩み、③が正しく重みを調整できる可能性がある。
3. ISAM2の`relinearize_threshold_`が、旋回による大きな非線形性の下で
   最適化の質を落としている可能性(未検証)。

## 追加検証: バイアスランダムウォークσ(候補1)は除外

`bias_acc_random_walk_sigma`/`bias_gyro_random_walk_sigma`を既定値の0.1倍〜100倍
(1000倍のレンジ)で振っても、t=15旋回窓のmax誤差は12.06〜12.13mmで**完全に
不変**だった(mean誤差はk=100で1.32→0.57mmまで下がるが、maxには効かない)。
候補1は12mmの下限要因ではないと確定。次の焦点は候補2(②の実共分散配信)に
絞られた。

## 現時点の結論

- 破綻(バグ)と過渡誤差(残差)は別問題。バグは解消済み
- 過渡誤差の所在(③の融合)と機序の方向性(IMU拘束過硬)は実証済み
- ただしIMU側のパラメータ調整だけでは5mm目標の下限(~12mm)を越えられない
- 次に切り分けるべきは上記候補1(バイアスσ)と候補2(②の実共分散)のどちらが
  12mmの下限を作っているか。候補2は17番で「大改造は不要」と判断していたが、
  今回IMU調整だけでは頭打ちになったことを踏まえ、再評価が必要かもしれない
