# Scan棄却方針の評価結果

このrunは入力監査用の最後のUnity通知時点でscan受信数が1件だけ遅れていたため、
通常構成の代表性能値には用いない。ただし、方針評価としての結論は明確である。

- `/odom_fast`未カバーscanを50 ms後に一律棄却する実装では、2425受信scan中551件
  (22.7%)を棄却し、最大連続棄却は21件(約0.53秒)に達した。
- その区間のIMUのみ外挿が最大105.95 mmまで増大した。
- よって、この単純棄却方針は不採用。入力IMUを捨てずscanを保留・時刻整合して
  処理できるよう、scan matchingの受信/ICP実行分離を検討する。

入力の完全欠損を示す証拠ではない。`source_scan_last=2420`に対し
`receiver_at_last_report=2419`であり、監査通知との競合による未到達1件の可能性を
残すため、比較性能データとしては保守的に除外する。
