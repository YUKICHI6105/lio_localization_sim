## 0. この文書の目的

本書は、3輪オムニホイール式ロボットのUnityシミュレーションおよび将来の実機に対して、

- 人間が競技戦略を判断するセミオート方式
- プリセット単位の自動走行
- 可能な限り短い走行時間
- 通常運動時の高精度自己位置推定
- 目標地点での静止精度10 mm
- 実機調整作業の最小化
- 実行時の計算負荷抑制

を同時に実現するための、実装AI向けの設計指示である。

本書の方針は、単純な「waypoint列を滑らかにつなぐ」だけではなく、最終的には、

> **実機制約を含む自由終端時間の最小時間軌道最適化をオフラインで行い、オンラインでは保存済み軌道を軽量なfeedforward＋feedbackで追従し、反復試験からILCで定常誤差を学習する**

構成を目標とする。

ただし、最初から全機能を同時実装しない。  
まず既存システムを壊さずに基準軌道生成と追従を成立させ、その後に最小時間最適化、TVLQR、ILCを段階的に追加する。

# 4. 重要な設計判断

## 4.1 スプラインは力学制約を自動的には満たさない

スプラインが与えるのは、空間上の経路だけである。

```math
\mathbf r(s)=
\begin{bmatrix}
x(s)\\
y(s)
\end{bmatrix}
```

時間軌道は、

```math
\mathbf p(t)=\mathbf r(s(t))
```

として初めて定義される。

弧長パラメータを使うと、

```math
\dot{\mathbf p}
=
\mathbf t(s)\dot s
```

```math
\ddot{\mathbf p}
=
\mathbf t(s)\ddot s
+
\mathbf n(s)\kappa(s)\dot s^2
```

となる。

したがって、

- 接線方向加速度：`a_t = s̈`
- 法線方向加速度：`a_n = κv²`

であり、等方的な加速度円近似では、

```math
a_t^2 + (\kappa v^2)^2 \le a_{\max}^2
```

を満たす必要がある。

結論：

> **スプライン生成だけでは不十分。経路形状と速度・加速度・姿勢・入力を同時に評価する必要がある。**

## 4.2 最速を狙う最終手法

最終的な本命は、

> **自由終端時間の最小時間軌道最適化**

とする。

候補手法：

1. Direct collocation
2. Direct multiple shooting
3. スプライン候補＋TOPP-RA相当の時間パラメータ化は比較基準として残す

最初の実装はdirect collocationを推奨する。

理由：

- 状態、入力、終端時間を同時に最適化しやすい
- 壁、各輪推力、速度、加速度、姿勢、終端条件を直接制約にできる
- オフライン計算なので重くてもよい
- プリセットごとに計算結果を保存できる

## 4.3 オンラインでMPCC/NMPCは原則使わない

現段階では、

- フィールドが既知
- プリセットが既知
- 通常時の自己位置推定精度が高い
- オンラインCPU負荷を抑えたい
- 競技戦略は人間が判断する

ため、オンラインで毎周期大規模最適化を行う必要性は低い。

オンライン処理は、

- テーブル参照
- 軌道位相同期
- feedforward
- PDまたはTVLQR
- 安全監視

に限定する。

# 5. 軌道最適化問題

## 5.1 状態

最低限：

```math
\mathbf x=
\begin{bmatrix}
x & y & \theta & v_x & v_y & \omega
\end{bmatrix}^{\mathsf T}
```

必要に応じて追加：

- 各輪角速度
- 各輪電流
- モータ一次遅れ状態
- 吸引物の簡易状態
- バッテリー電圧依存状態

## 5.2 入力

最終形では各輪推力または各輪トルク：

```math
\mathbf u=
\begin{bmatrix}
F_1 & F_2 & F_3
\end{bmatrix}^{\mathsf T}
```

MVPでは車体座標の仮想加速度入力でもよい：

```math
\mathbf u=
\begin{bmatrix}
a_x & a_y & \alpha
\end{bmatrix}^{\mathsf T}
```

ただし、最速性能評価では最終的に各輪制約へ移行する。

## 5.3 運動方程式

簡略モデル：

```math
\dot x = v_x
```

```math
\dot y = v_y
```

```math
\dot \theta = \omega
```

```math
m\dot{\mathbf v}
=
\mathbf F_{\mathrm{body}} - \mathbf F_{\mathrm{loss}}
```

```math
I_z\dot\omega
=
\tau_z - \tau_{\mathrm{loss}}
```

各輪推力から車体力・ヨートルクへ変換：

```math
\begin{bmatrix}
F_x\\
F_y\\
\tau_z
\end{bmatrix}
=
B(\theta)
\begin{bmatrix}
F_1\\
F_2\\
F_3
\end{bmatrix}
```

実機移行時は、必要に応じて一次遅れを追加する。

```math
\tau_a \dot{\mathbf a}_{\mathrm{actual}}
+
\mathbf a_{\mathrm{actual}}
=
\mathbf a_{\mathrm{cmd}}
```

## 5.4 目的関数

第一目的：

```math
\min T
```

ただし、実機追従可能性のために微小な正則化を追加する。

```math
J
=
T
+
\epsilon_u
\int_0^T
\|\dot{\mathbf u}(t)\|^2dt
+
\epsilon_c J_{\mathrm{clearance}}
```

`ε`は走行時間最小化を壊さない程度に小さくする。

## 5.5 必須制約

### 始端条件

```math
\mathbf x(0)=\mathbf x_{\mathrm{start}}
```

### 終端条件

停止地点では：

```math
\|\mathbf p(T)-\mathbf p_{\mathrm{goal}}\|
\le e_{\mathrm{goal}}
```

```math
\|\mathbf v(T)\|
\le v_{\mathrm{goal}}
```

```math
|\theta(T)-\theta_{\mathrm{goal}}|
\le e_{\theta}
```

```math
|\omega(T)|
\le \omega_{\mathrm{goal}}
```

静止精度10 mmを狙う場合、最適化上の終端位置許容値は5～8 mm程度を目安とする。

### 速度制約

```math
\|\mathbf v\|
\le v_{\max}
```

### 角速度制約

```math
|\omega|
\le \omega_{\max}
```

### 各輪推力制約

```math
|F_i|
\le F_{i,\max}(\omega_i,V_{\mathrm{battery}})
```

### 入力変化制約

可能なら：

```math
|\dot F_i|
\le \dot F_{i,\max}
```

### 壁・木枠との衝突回避

ロボット中心ではなく、機体フットプリント全体で判定する。

```math
d_{\mathrm{robot}}(\mathbf x,\mathcal O)
\ge d_{\mathrm{margin}}
```

安全余白には次を含める。

- 自己位置推定誤差
- 高速追従誤差
- フィールド施工誤差
- 機体寸法誤差
- 吸引・展開機構の張り出し

### 通過領域制約

waypoint一点通過ではなく、許容コリドーやゲート領域を使用する。

### 回収イベント制約

回収時に必要な条件：

- 吸引部位置
- 機体姿勢
- 相対速度
- 速度上限
- 保持確認
- 必要なら一時停止

### 積載時制約

箱保持中は空荷より厳しい制約を用意する。

例：

```math
\sqrt{a_x^2+a_y^2}
\le a_{\mathrm{loaded}}
```

必要に応じて、

- ヨー角加速度
- 吸引部から箱重心までの距離
- 慣性モーメント
- 吸着面法線方向の力
- 脱落判定モデル

を追加する。

# 7. 大域的局所解対策

障害物付き最小時間問題は非凸であり、一回の最適化で絶対的な大域最適解は保証されない。

したがって、複数初期解を用意する。

例：

- 左寄り経路
- 右寄り経路
- 最短距離寄り
- 曲率を抑えた大回り
- 回転を早く終える姿勢計画
- 回転を遅らせて並進を優先する計画
- 空荷最速
- 積載安全

各候補について最適化し、次で順位付けする。

1. 制約違反なし
2. 高密度再検証合格
3. 総所要時間
4. 最小壁余裕
5. 追従シミュレーション誤差

# 9. オンライン追従

## 9.1 基本式

MVP：

```math
\mathbf a_{\mathrm{cmd}}
=
\mathbf a^\star
+
K_p(\mathbf p^\star-\hat{\mathbf p})
+
K_d(\mathbf v^\star-\hat{\mathbf v})
```

ヨーも同様：

```math
\alpha_{\mathrm{cmd}}
=
\alpha^\star
+
K_{p,\theta}e_\theta
+
K_{d,\omega}e_\omega
```

最終形：

```math
\mathbf u
=
\mathbf u^\star
-
K(t)(\hat{\mathbf x}-\mathbf x^\star)
+
\Delta\mathbf u_{\mathrm{ILC}}
```

## 9.2 feedforwardの意味

- 基準入力：理想運動を先回りして発生
- feedback：モデル差、推定誤差、外乱による差だけ修正
- ILC：毎回同じ場所で出る再現性のある誤差を次回から先回りして補正

## 9.3 時刻だけに盲従しない

単純な時刻同期だけでは、一時的な遅れから無理に追いつこうとする。

現在位置から軌道進行度を求める。

```math
\hat s
=
\arg\min_s
\|\hat{\mathbf p}-\mathbf p^\star(s)\|^2
```

全探索はせず、前回インデックス周辺だけ探索する。

例：

```text
previous_index - 5
～
previous_index + 20
```

線分射影によりサンプル間を補間する。

通常時：

- 時刻基準を主体
- 現在位置進行度で微調整

大きな遅れ：

- 現在位置に近い位相へ再同期
- 過大な追いつき加速を禁止

停止フェーズ：

- 時刻同期を弱める
- 最終位置・姿勢への収束を優先

# 10. 追従器の段階

## Stage A：既存Cartesian PD

既存の、

```text
F = m * (Kp * position_error + Kd * velocity_error)
```

を基準として残す。

まず新しい基準軌道だけを与え、追従性能を測る。

## Stage B：加速度feedforward付きPD

基準加速度を追加する。

オンライン計算量はほぼ増えないため、費用対効果が高い。

## Stage C：TVLQR

最適軌道周りでモデルを線形化し、Riccati方程式を後ろ向きに解いて `K(t)` を保存する。

実行時は行列積だけなので軽量。

TVLQR導入条件：

- PDで軸間結合誤差が残る
- 並進とヨーの同時動作で誤差が増える
- 各方向の応答差が大きい
- 最小時間軌道付近でPD調整が難しい

## Stage D：LTV-MPC

TVLQRで扱えない入力制約が実走行で問題になった場合のみ検討する。

オンラインNMPC/MPCCは、必要性が実測された場合のみ候補とする。

# 11. 精密停止モード

高速走行制御と静止保持を完全に同一設定にしない。

## 11.1 切替条件

例：

- 終端まで100～200 mm
- 基準速度が閾値以下
- 終端フェーズに入った
- 位置誤差が一定以下

## 11.2 精密停止時

- 目標速度：0
- 目標加速度：0
- feedforwardを停止または弱める
- 最終位置・姿勢を直接保持
- 必要ならDゲインを下げる
- 必要なら速度推定を軽く低域通過
- 必要なら小さなI項または不感帯補償を目標近傍だけ有効化

## 11.3 到着判定

瞬間判定にしない。

例：

```text
position_error < 5～8 mm
speed < 10～20 mm/s
yaw_error < specified tolerance
yaw_rate < specified tolerance
```

を200～500 ms連続で満たしたら到着。

既存のピックアップ判定：

```text
位置誤差 <= 5 mm
速度 <= 10 mm/s
```

は維持できるようにする。

## 11.4 機構先端基準

静止精度10 mmの最終評価対象が吸引部または投入部なら、機体中心ではなく機構先端を基準にする。

```math
\mathbf p_{\mathrm{tool}}
=
\mathbf p_{\mathrm{body}}
+
R(\theta)\mathbf r_{\mathrm{tool}}
```

位置とヨー誤差を合わせて機構先端誤差を評価する。

# 12. ILC（反復学習制御）

## 12.1 目的

シミュレーションと実機の差のうち、毎回同じ場所で発生する再現性のある誤差を学習する。

例：

- タイヤ摩擦の方向依存
- モータ個体差
- 重心偏り
- 一定遅延
- 特定カーブで毎回同じ横ずれ
- バッテリー条件に対する定常差

## 12.2 更新式の基本形

```math
\mathbf u_{k+1}(s)
=
\mathbf u_k(s)
+
L\mathbf e_k(s)
```

時間基準より、軌道進行度 `s` 基準を推奨する。

## 12.3 更新対象

安全上、PWMを直接学習するより、

- 車体加速度feedforward
- 車輪力feedforward
- 速度feedforward
- 位相補正量

を学習対象にする。

## 12.4 学習禁止条件

以下の試行はILC更新に使用しない。

- 衝突
- 自己位置推定の大きなジャンプ
- ICP異常
- ノーツ／箱の脱落
- 車輪出力の長時間飽和
- 安全余白違反
- 実行中の人間介入
- タスク条件の不一致
- 前回と異なる非再現性誤差
- センサ欠落
- 非常停止

## 12.5 更新制限

- 学習率に上限
- 1回あたりの補正量上限
- 全体入力上限
- 周波数帯制限
- 高周波補正を抑制
- 更新後にシミュレーション再検証
- 性能悪化時にロールバック

# 13. 実機モデル同定

完全なデジタルツインを作る必要はない。

まず次を実測する。

## 13.1 加速試験

複数方向で、

- 指令加速度
- 実加速度
- 車輪速度
- モータ電流
- バッテリー電圧
- 応答遅延

を記録する。

空荷と積載を分ける。

## 13.2 制動試験

複数速度から停止させ、

- 最大減速度
- 停止距離
- 停止時間
- オーバーシュート
- 進入方向依存

を測定する。

## 13.3 並進・回転同時試験

並進しながらヨー加速し、並進能力がどれだけ低下するか測定する。

## 13.4 保持限界試験

箱保持状態で、

- 前後加速度
- 横加速度
- ヨー角加速度
- ジャーク

を上げ、脱落・ずれの境界を測定する。

## 13.5 モデル更新

同定結果から、

- 最大出力
- 方向依存加速度集合
- 一次遅れ時定数
- 空荷／積載制約
- 回転との出力競合

を更新する。

# 14. 速度を安全に上げる自動試験

初回から100%最小時間軌道を実行しない。

速度倍率または入力倍率を段階的に上げる。

例：

```text
0.60
→ 0.70
→ 0.80
→ 0.87
→ 0.92
→ 0.96
→ 1.00
```

次段階へ進む条件：

- 衝突なし
- 最大追従誤差が基準内
- 静止誤差10 mm以内
- 壁クリアランス基準内
- 車輪飽和率が基準内
- 箱保持成功
- 自己位置推定が正常
- 安全監視に異常なし
- 複数回連続成功

人間が次段階への承認を行える構成にする。

# 16. 安全監視

競技中および試験中はSafety Supervisorを独立させる。

監視対象：

- 壁・木枠との予測最小距離
- 自己位置推定の急変
- IMU異常
- 車輪速度と機体速度の不整合
- 長時間の入力飽和
- 箱保持センサ
- 機構異常
- 人間の停止入力
- 非常停止
- 予定コリドー逸脱
- 終端位置超過

通常中断：

- 最短安全停止軌道
- 位置保持
- 人間の次指示待ち

非常停止：

- 直ちに安全側へ出力遮断
- ILC学習禁止
- 試行無効化

# 17. 既存コードへの統合

## 17.1 `BuildRoute()`

現状：

- Start
- Pickup
- SlalomWaypoints
- Finish

のwaypoint列を生成。

当面はこの出力を、基準経路候補または最適化初期解として使用する。

将来はPresetDefinitionから、

- タスク列
- コリドー
- 始端・終端
- フェーズ境界
- 機構イベント

を生成する。

## 17.2 `BuildTimeline()`

現状の各セグメント独立5次多項式生成を置き換える。

MVP：

- 事前生成した軌道テーブルをロード
- または起動時に単純スプライン＋速度計画を生成

最終形：

- オフライン最適化済み軌道データをロード
- 時刻、状態、入力、フェーズ、イベントを保持

## 17.3 `EvaluateRoute()`

新しい役割：

入力：

```text
elapsed_time
estimated_state
previous_progress
```

出力：

```text
reference_position
reference_velocity
reference_acceleration
reference_yaw
reference_yaw_rate
reference_yaw_acceleration
reference_input
phase_id
task_event
done
```

内部処理：

1. 時刻基準の位相を計算
2. 現在位置から進行度を局所探索
3. 位相を安全に融合
4. 軌道テーブルを補間
5. フェーズ・イベントを返す

## 17.4 `FixedUpdate()`

段階的に変更する。

Stage A：

- 現行PDを維持
- 新しい位置・速度参照を使用

Stage B：

- 加速度feedforwardを追加

```text
force =
mass * (
    reference_acceleration
  + Kp * position_error
  + Kd * velocity_error
)
```

Stage C：

- TVLQRまたは軌道追従行列を使用

Stage D：

- ILC補正を追加

## 17.5 `StartNextLap()`

- 復路用プリセットまたは復路軌道IDを選択
- 前ラップ終端状態を次プリセット始端へ引き継ぐ
- 位相、ILC状態、イベント状態をリセット
- 復路専用バイパスロジックは初期解生成に再利用可能

## 17.6 ピックアップ停止

既存の、

```text
位置誤差 <= 5 mm
速度 <= 10 mm/s
```

まで待機する仕組みは維持する。

ただし将来、走行中回収が成立する場合は、

- 完全停止回収
- 低速通過回収

をPresetDefinitionで切り替えられるようにする。

## 17.7 `EnableExtraSpins`

軌道検証用スピンは、通常最速プリセットと分離する。

推奨：

- `ValidationMode`でのみ有効
- スピン地点を独立フェーズとして挿入
- 通常最速プリセットには含めない
- スピン前後は速度ゼロを強制
- 自己位置推定評価ログへ明示する

# 19. 実装フェーズ

## Phase 0：計測と回帰テスト

必須：

- 現行6.53 s基準の再現
- 現行追従誤差ログ
- 自己位置推定誤差ログ
- 衝突有無
- 壁距離
- 停止精度
- 現行PD出力
- 既存機能の回帰テスト

成果物：

- 基準CSV
- 自動評価スクリプト
- 成否判定
- 既存挙動の動画または再生ログ

## Phase 1：軌道テーブル方式

目的：

- 各waypointで速度ゼロになる現行問題を除去
- `EvaluateRoute()`をテーブル補間方式へ変更
- 既存PDは維持

実装：

- C²スプラインまたは滑らかな基準経路
- 弧長サンプリング
- 単純forward-backward速度計画
- 時刻、位置、速度テーブル
- 既存ピックアップ停止維持

この段階では最適性より、軌道表現と実行パイプラインの成立を優先する。

## Phase 2：結合加速度制約

目的：

- 接線加速度と法線加速度の同時制約を正しく扱う

```math
a_t^2 + (\kappa v^2)^2 \le a_{\max}^2
```

- 速度プロファイルを反復forward-backwardで計算
- 高密度再検証を追加

## Phase 3：加速度feedforward

目的：

- 高速加減速時のPD遅れを減らす

実装：

- 基準加速度をTrajectorySampleへ追加
- `FixedUpdate()`でfeedforwardを追加
- 既存PDとのA/B比較

## Phase 4：位相同期

目的：

- 時刻遅れ時の無理な追いつき防止
- 実機差への耐性向上

実装：

- 前回インデックス近傍探索
- 線分射影
- 時刻位相と位置位相の融合
- 大遅れ時の再同期
- 停止フェーズで終端位置優先

## Phase 5：精密停止

目的：

- 95%以上で真値基準10 mm以内を狙う

実装：

- 精密停止モード
- 到着判定
- 機構先端誤差評価
- 姿勢精度評価
- 必要なら停止域だけ小さなI項／不感帯補償

## Phase 6：自由終端時間最小時間最適化

目的：

- 経路形状、速度、姿勢、入力、終端時間を同時最適化

実装候補：

- Python + CasADi + IPOPT
- Direct collocation
- プリセットごとの複数初期解
- 最適化結果をJSON/CSV/Binary assetとしてUnityへ出力

## Phase 7：実機モデル同定

目的：

- シミュレーション軌道を実機制約へ合わせる

実装：

- 加速試験
- 制動試験
- 並進・回転同時試験
- 積載試験
- モデルパラメータ更新

## Phase 8：TVLQR

目的：

- 最小時間軌道近傍で軽量かつ結合を考慮した追従

実装：

- 軌道点ごとの線形化
- Riccati後退計算
- `K(t)`保存
- オンライン行列積
- PDとの比較

## Phase 9：ILC

目的：

- 定常的な実機残差を自動補正
- 人間の手調整を削減

実装：

- 試行ログ
- 安全ゲート
- 進行度基準誤差
- feedforward更新
- 更新量上限
- ロールバック
- 自動比較レポート

## Phase 10：プリセット運用

目的：

- 人間が戦略を選び、ロボットが運動を最適実行する完成形

実装：

- プリセットUI
- 次プリセット予約
- 実行中断
- 安全停止
- 手動復帰
- 空荷／積載プロファイル切替
- 実行可否バリデーション

# 21. 受け入れ基準

## 21.1 軌道生成

- 中間waypointで不要に速度ゼロにならない
- 位置・速度が連続
- 加速度が有限
- 壁・木枠との干渉なし
- 高密度サンプリングで制約違反なし
- 終端速度ゼロ
- 回収・投入条件を満たす

## 21.2 追従

初期目標：

- 最大追従誤差：安全余白を侵食しない
- RMS追従誤差：10 mm級を目標
- 位相遅れ時に過大な追いつき加速をしない
- 出力方向を保ったまま飽和処理する
- 長時間の車輪飽和を起こさない

## 21.3 静止精度

目標：

- 真値基準で95%以上の試行が10 mm以内
- 推定値基準停止残差3～5 mm程度
- 到着後の真値振動幅5 mm以下を目標
- 姿勢誤差を含む機構先端誤差10 mm以内
- 到着判定は200～500 ms連続成立

## 21.4 最速性能

比較対象：

1. 現行独立5次多項式
2. C²経路＋単純速度計画
3. 結合加速度制約付き速度計画
4. 加速度feedforward付きPD
5. 最小時間direct collocation＋PD
6. 最小時間direct collocation＋TVLQR
7. ILC適用後

各方式で、

- 完走時間
- 最大／RMS追従誤差
- 壁余裕
- 飽和率
- 停止精度
- 箱保持率

を比較する。

# 22. 禁止・非推奨事項

- シミュレーションで得たPWM列をそのまま実機へ固定再生しない
- スプラインを作っただけで力学制約を満たしたとみなさない
- 中間waypointをすべて強制停止点にしない
- 各軸を独立clipして加速度ベクトル方向を変えない
- 時刻参照だけに盲従して遅れを無理に取り戻さない
- 衝突試行をILC学習に使わない
- 自己位置異常を定常誤差として学習しない
- 最初から100%限界軌道を実機で走らせない
- 最小時間だけを見て追従可能性を無視しない
- いきなりオンラインNMPC/MPCCへ移行しない
- 実機モデルを完全再現しようとして開発を止めない
- 平均誤差だけで10 mm精度達成と判定しない

# 23. 実装AIへの具体的指示

1. まず既存コードを読み、現在の挙動・依存関係・テスト可能範囲を整理すること。
2. 既存機能を壊す大規模置換を一度に行わないこと。
3. 各Phaseを独立コミット可能な単位に分けること。
4. 旧方式と新方式を実行時フラグで比較可能にすること。
5. 数式とコードの対応をコメントで明示すること。
6. 速度・加速度・単位系を明示し、フィールド座標とUnity座標の変換を一箇所へ集約すること。
7. すべての軌道生成後に高密度再サンプリング検証を行うこと。
8. 数値異常、NaN、負の平方根、ゼロ除算、非単調時刻テーブルを検出すること。
9. 速度プロファイルが収束しない場合は失敗として扱い、楽観的な結果を返さないこと。
10. 追従ログと評価指標を同時に実装すること。
11. UIや可視化より先に、データ整合性と再現性を確立すること。
12. 実装前に変更対象、非変更対象、受け入れ試験を提示すること。
13. 各Phase完了時に、現行基準との定量比較を報告すること。
14. 最終的な最小時間軌道は、実機計測で得た制約を使用して再生成できる設計にすること。
15. 不明な機体パラメータを推測で固定せず、設定ファイルまたは同定対象として分離すること。

# 24. 最終ゴール

完成形は次である。

```text
人間：
「初手・右2個回収→ビンゴ前」を選択

ロボット：
・事前生成済みの最小時間軌道をロード
・自己位置から現在位相を同期
・基準feedforwardを出力
・PDまたはTVLQRで小誤差を補正
・積載状態の制約を守る
・ビンゴ前で10 mm級の精密停止
・ログを自動評価

走行後：
・衝突や異常がない試行だけILCへ入力
・再現性のある誤差を次回feedforwardへ反映
・速度段階を安全に上げる

人間：
・戦略と安全承認だけ担当
```

最終的な設計思想は、

> **重い最適化は事前に済ませる。実行時は軽量に追従する。実機差は反復学習で埋める。人間は戦略と安全判断に集中する。**

である。
