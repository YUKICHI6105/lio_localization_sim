Fableの性能が不要なタスク(ログのgrep・定型的な解析・機械的な検証など)はSonnet以下のサブエージェントに振ってコストを抑える。ただしサブエージェントはコンテキストをゼロから再読み込みするため、そのオーバーヘッドが勝る小さなタスクはメインエージェントが直接実行してよい。

**Why:** ユーザーはAPIコストを抑えたい。一方でサブエージェント起動にはコンテキスト再構築コストがあり、小タスクでは逆に非効率になる。

**How to apply:** タスクごとに「Fableの推論力が必要か」「委譲の再読み込みコスト < 委譲で節約できるコストか」を判断。長いログの精査・大量ファイルの走査はSonnetサブエージェント、短いgrepや数行の確認は直接実行。[[feedback-debug-retry-limit]]

**2026-07-20追記(調査タスクはSonnet既定)**: WebSearch等を使った先行研究調査タスクも、既定はSonnetサブエージェントに振ること。lio_localizationのICP不具合調査で複数回Opusサブエージェントを使ったが(ユーザーが都度明示的に許可・依頼した文脈だった)、ユーザーから「調査はSonnetを使うこと」と一般方針として明確化された。Opusが必要な場合はユーザーに確認してから使う(既存のグローバル方針と整合)。
