# Rebuilding this environment from scratch

Cloning the repositories restores the *source*. It does not restore the toolchain they build
against, the Windows-side Unity project, or the machine tuning that made the simulation run
reliably. This is the rest of it.

Recorded from the working machine on 2026-07-25.

## What the environment was

| Component | Version |
|---|---|
| Host | Windows + WSL2, 15.7 GB RAM |
| Distro | Ubuntu 26.04 LTS |
| ROS 2 | `lyrical` (installed at `/opt/ros/lyrical`) |
| Unity Editor | `6000.5.5f1` |
| GTSAM | built/installed separately — `CMakeLists.txt` calls `find_package(GTSAM REQUIRED)` directly rather than declaring a ROS dependency |

## 1. WSL memory limits — do this first

Copy `wslconfig.txt` in this directory to `C:\Users\<you>\.wslconfig`, then run
`wsl --shutdown` from PowerShell.

Without it WSL sizes its VM at half the host RAM and never hands memory back to Windows. On
this machine that starved the Unity Editor and caused an out-of-memory crash during graphics
initialisation, and later contributed to transport stalls that killed measurement runs.

## 2. Workspace layout

```
ros2_ws/
├── docs -> src/lio_localization/docs      # symlink, recreate with: ln -s src/lio_localization/docs docs
└── src/
    ├── lio_localization/                  # localisation package + reference docs (main.md lives here)
    ├── lio_localization_sim/              # this repo: simulator, tooling, measurements
    ├── sotoba/                            # ICP library — NEEDS the fork, see below
    ├── ROS-TCP-Endpoint/                  # Unity <-> ROS bridge
    └── (can_plugins2, odometry_plugins, robomas_*, solenoid_valve_ros2)
```

`sotoba` must come from the fork, not upstream: `lio_localization` includes
`sotoba/icp_resource/normal_known_icp.hpp`, and the adaptive convergence test and
point-to-point best-of-N it relies on exist only in the fork's `main`.

```bash
git clone https://github.com/YUKICHI6105/sotoba.git src/sotoba
cd src/sotoba && git remote add upstream https://github.com/Stew-000-1-0-011/sotoba.git
```

Check out the working branches, not `master`:
`lio_localization` → `feature/icp-covariance`, `lio_localization_sim` → `feature/eval-fidelity`.

## 3. Build

```bash
source /opt/ros/lyrical/setup.bash
colcon build --symlink-install
```

Note: sourcing the ROS setup scripts fails under `set -u` (`AMENT_TRACE_SETUP_FILES: unbound
variable`). Scripts here wrap it in `set +u` / `set -u`.

## 4. Unity project

The source of truth is `unity/Robocon2026Sim/` in this repo — Assets, Packages,
ProjectSettings only. `Library/`, `Temp/` and `Logs/` are regenerated by Unity.

Deploy it to the Windows side (the Editor must run from a Windows path, not `/mnt/...`).
The tracked launch and deployment scripts target
`C:\\Users\\kouza\\UnityProjects\\Robocon2026Sim`; set
`ROBOCON_UNITY_WINDOWS_PROJECT` when using another Windows profile or location.

The scene is built procedurally by `SimulationBootstrap`'s `RuntimeInitializeOnLoadMethod`
hook, so opening the project and pressing Play is enough — there is no scene asset to load.

Unity restores its packages from `Packages/manifest.json` on first open, including the ROS TCP
Connector and the MCP integration used to drive Play from outside the Editor.

## 5. Running a measurement

Order matters: start ROS first, wait for its READY marker, then press Play. Unity registers
its publishers in `Start()`, so a Unity session that begins before the endpoint is listening
never publishes.

```bash
bash src/lio_localization_sim/scripts/stage4_sweep_run.sh off 0.15 0.003 1
```

`docs/stage4_resume_notes.md` covers the operational pitfalls found the hard way: stale
endpoints holding port 10000, publisher queue sizing against the 1 kHz IMU, and why a run must
never be judged from an open-loop session.
